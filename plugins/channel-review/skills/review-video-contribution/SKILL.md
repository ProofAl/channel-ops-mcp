# Review video contribution

Work in the user's language from the nonpersonal totals they choose to share in this conversation. The workflow requires no account connection, installation or external destination.

## Establish the decision

Identify the video or campaign, the decision, reporting dates, currency and attribution window. If the user provided enough information, calculate immediately. If an essential input is missing, return any supported partial result and ask one focused question. A useful opening request is the period's total settled receipts, source overlap and direct costs. Accept per-source aggregates or anonymous order labels. Keep names, emails, payment details, private links and credentials out of the review.

## Reconcile evidence

1. Start with settled payments. Keep leads, orders awaiting payment, visits and views in separate columns. Write down the unit counted (orders, unique customers or bookings) and use one unit per denominator.
2. Assign each settled order once, at its finest supported level. **Release-linked** means an order can be matched to a release-specific tag or code by the stated rule. **Reported only** means an unmatched paid customer's intake or sales call names the channel or release. Preserve that distinction. **Other known** means another source was identified. **Unknown** is the remainder when the complete, comparable total is available. Treat a shared profile link as channel-level evidence. A customer mentioning two channels supplies a multi-touch observation.
3. Remove overlap before summing, using anonymous order matches or the comparable intersecting count supplied by the user. If overlap is unknown, keep the source counts separate. With group sizes A and B from the same population of size N, the number covered by either is between max(A,B) and min(N,A+B). Unequal order values prevent a count bound from establishing a cash bound. A repeated purchase can count as another settled order while the number of new paying customers stays the same.
4. Check that classified counts and cash reconcile to the supplied total for the same dates, currency and scope. If they do not reconcile, flag the discrepancy and report only the supported breakdown. Treat an absent value as unknown. A tracking link establishes an observed association. Causal lift requires a comparison that supports it.

## Calculate a decision

For a named release, start with its linked gross cash. Subtract refunds, fulfillment and payment fees attributable to those orders, and the release's production, distribution and team-time costs. Count each outlay once. When the input is already net of refunds or fees, do not deduct them again. Show labor hours × the disclosed loaded rate. If a cost is unknown, give the subtotal and the missing amount, or calculate a clearly labeled sensitivity. Keep currencies separate unless the user supplies a dated conversion rule.

Show reported-only sales in a separate line at their known level. An optional broader channel scenario may include mutually exclusive channel-reported receipts and their associated variable costs. Label its scope, assumptions and included campaign costs. A channel mention alone cannot establish which release deserves credit. Allocate shared costs only under a stated rule. Refer to [the worked case](references/worked-case.md) when comparing a release with a channel-level scenario.

Close with the decision the user asked for. If ranking topics, use comparable offers, conversion windows and cost coverage. Give one action and the observation that would change it. A channel-only signal can justify a small test of a topic or a better source question. It cannot rank individual episodes. If costs or sales are missing, explain what can be learned from the available evidence and suggest the smallest change to the next release that makes the choice measurable.
